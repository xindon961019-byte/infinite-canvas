# 多设备增量同步

## 行为

同一账号的设备共享服务器工作空间。上传逐条合并本地新增和修改，拉取逐条合并服务器变更；双方独有的记录保留。本地 A、B、C 与服务器 D、E、F、G、H 同步后可得到八条记录。没有变化时不再提交记录或上传媒体。

本地缺失不是删除指令。本轮不传播删除，也不按时间戳决定谁覆盖谁。两端都改动同一记录时，界面让用户选择本地或服务器版本；遇到选择后再次发生的并发修改，服务器返回 409，保留已完成记录并允许重试。

## 数据范围

| 数据 | 合并单位 |
| --- | --- |
| 画布 | 项目 ID，不自动拼接同一项目的节点 |
| 我的素材、主体、图片与视频生成记录 | 各自记录 ID |
| AI 工作台 | 一份完整草稿，冲突时选择版本 |
| 模型配置 | 单个配置字段、渠道基本资料、每个渠道模型及其脚本 |
| WebDAV | 每个配置字段，包含账号和密码 |
| 浏览器偏好、Agent 连接配置与 Token | 应用自身 localStorage 键 |
| 插件配置和提示词缓存 | app_state / prompt_cache 中对应存储记录 |
| 主体音色、图片、画布及素材引用媒体 | SHA-256 文件引用，按账号空间去重 |

服务端登录会话、同步游标、失败重试暂存和恢复日志不作为业务记录同步。磁盘上的 Agent 对话、Skill 文件不属于浏览器本地存储，本实现不会冒充已备份这些文件。没有业务引用的媒体缓存不上传。

API Key、WebDAV 密码、渠道脚本及 Agent 连接 Token 会进入账号私有备份；当前没有端到端加密，具备数据库访问权限的服务器管理员可读取清单，接口和日志不会展示密钥值。

## 协议与存储

- 浏览器先捕获本地数据，并拆分为独立记录清单。记录键为 `[域名, 集合名, 记录 ID]` 的 JSON UTF-8 SHA-256；非集合数据使用 `singleton`。
- 内容摘要不包含捕获时间、设备 clientId 或本地媒体存储键。文件与媒体引用排序固定，避免恢复后重复认定为修改。
- 只为变化的记录调用已有备份创建、媒体补传和提交接口。记录清单的 `clientId` 为 `sync-record-v1`，不会出现在可整体恢复的历史备份列表中。
- `POST /api/cloud/v1/sync` 接收 `key / backupId / baseRevision`。只允许发布当前工作空间已提交的单记录版本；服务端核对 ID、事务锁定工作空间、检查旧版本，然后更新该记录。其他记录不动。
- `GET /api/cloud/v1/sync?after=<revision>` 返回当前工作空间的变更索引，沿用服务端已有分页大小。以最后一项的版本继续读取，空数组结束。
- 本地同步状态按服务器 ID 与工作空间 ID 隔离。上传读取服务器索引以检查冲突；拉取从上次成功游标继续。当前会扫描本地数据计算差异，上传索引扫描也不是零开销，但业务正文和媒体按变更传输。
- 下载先验证清单和文件摘要；每条记录与其本地同步基线一同在 IndexedDB 事务中提交。取消或失败不会回滚前面已完成的记录，重试跳过已完成版本。
- 配置在 localStorage，不能声称与 IndexedDB 原生原子提交。持久化 journal 记录提交前后值，IndexedDB 提交标记决定重启后恢复哪一份；应用加载业务 store 前先恢复未完成 journal。

## 主体长期使用

主体仍以本地持久化为主，同步后服务器提交的记录与媒体绑定长期保留。临时访问授权到期不删除媒体。当前同步版本被保护，不能通过删除备份接口删除；再次使用时可按摘要复用服务器文件并申请新授权。恢复到新设备后，媒体写回本地稳定存储引用。

## 后端升级

同级 `infinite-canvas-cloud` 增加 `sync_records` 表，数据库版本从 2 升为 3，迁移只新增索引表并保留已有备份与媒体。生产已完成备份、迁移与发布，详见 `deploy/README.md`。其他部署需先运行项目现有 migrate 命令，再启动新后端。旧后端不声明 `incrementalSync` 时，前端拒绝进入同步写入。

原有完整备份可通过「恢复历史备份」独立入口使用；它仍是显式替换恢复。旧历史快照不会自动导入当前同步索引，先恢复所需快照到一个设备，再上传即可建立索引。

## 验证

- 前端五项记录合并测试通过：3+5 合并、幂等、同 ID 修改、媒体引用重定位、配置记录保留。
- Go 的记录键、配置域、既有业务域和严格 JSON 契约测试通过。
- 发布幂等、并发冲突、无关记录保留、跨账号隔离的 PostgreSQL 集成用例已在服务器独立测试容器通过，未使用生产数据库。
- 部署时 Vite 生产构建通过，生产数据库升级成功；未执行类型检查，真实双设备、配置中断恢复及模型公网媒体读取仍需人工验收。
