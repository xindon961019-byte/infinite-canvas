# Infinite Canvas 独立后端接入设计

## 1. 文档目的

本文定义在不改变 Infinite Canvas 本地优先定位的前提下，接入独立后端仓库 `infinite-canvas-cloud` 的方案。后端用于服务器备份与恢复、跨设备同步、媒体托管，以及为 MiniMax H3、Seedance 2.5 等只接收远程媒体地址的视频渠道提供参考图片、视频和音频 URL。

本方案优先控制前端改动范围，使当前仓库可以继续同步上游 fork。未配置云服务时，现有浏览器本地存储、WebDAV、AI 渠道直连和本地代理行为保持不变。

本文是接入设计，不代表相关能力已经实现。文中的文件大小、存储配额、并发数、超时、重试次数、媒体访问有效期和快照保留数量均标记为待确认，实施前必须根据实际渠道和部署环境确认。

## 2. 设计结论

采用独立后端仓库和前端薄适配层：

```text
上游仓库
    │ 定期同步
    ▼
infinite-canvas（当前 fork）
├── React/Vite 前端
├── localforage 本地业务数据
├── WebDAV 可选同步
└── Cloud Client 可选接入层
         │ HTTPS
         ▼
infinite-canvas-cloud（独立仓库）
├── 鉴权
├── 同步清单与快照
├── 媒体上传与下载
├── 临时模型访问地址
└── 文件索引或数据库
```

核心原则：

1. 浏览器本地数据仍是编辑过程中的即时数据源。
2. 后端不可用时不阻塞画布编辑、本地素材管理和现有 AI 渠道调用。
3. 云端能力必须显式配置，默认关闭。
4. 前端通过稳定协议访问后端，不依赖后端内部数据库或文件目录。
5. 结构化数据和媒体文件分开处理。
6. 媒体按内容哈希去重，业务记录只引用文件 ID。
7. 私有备份地址与模型临时访问地址分离。
8. AI API Key、WebDAV 密码和云服务访问令牌默认不参与同步。
9. 第一版先实现备份与恢复，不静默启用多设备自动双向合并。
10. 后端能力按阶段增加，先解决参考媒体 URL，再接入完整数据同步。

## 3. 当前项目基线

### 3.1 当前运行方式

当前线上应用是由 Nginx 提供的 Vite 静态站点。浏览器直接访问用户配置的 AI 渠道，项目没有负责用户账号、业务数据库和媒体上传的云端服务。

### 3.2 当前数据位置

| 数据 | 当前保存位置 | 说明 |
| --- | --- | --- |
| 画布项目 | 浏览器 localforage | 本地业务数据 |
| 我的素材 | 浏览器 localforage | 元数据与媒体引用 |
| 图片文件 | `image_files` localforage 实例 | 通过 `image:<id>` 类型的 `storageKey` 引用 |
| 视频、音频文件 | `media_files` localforage 实例 | 通过 `<type>:<id>` 类型的 `storageKey` 引用 |
| 图片生成记录 | 浏览器 localforage | WebDAV 同步域为 `image-logs` |
| 视频生成记录 | 浏览器 localforage | WebDAV 同步域为 `video-logs` |
| 渠道配置与 API Key | 浏览器本地 | 不经过项目后端 |
| WebDAV 配置 | 浏览器本地 | 用户自行提供远程存储 |

### 3.3 可以复用的现有能力

`web/src/services/app-sync.ts` 已经能够按业务域整理数据、收集媒体文件、生成文件清单、比较本地与远端文件、上传变化文件、合并远端数据、恢复媒体到 localforage，并汇报同步进度。

`web/src/services/image-storage.ts` 和 `web/src/services/file-storage.ts` 已提供通过 `storageKey` 读取本地 Blob 的入口。云端接入应复用这些入口，不改变画布节点对本地媒体的引用方式。

## 4. 目标与非目标

### 4.1 第一阶段目标

- 将本地人物图片、参考音频或参考视频上传到自己的服务器；
- 后端返回稳定的媒体文件 ID；
- 前端可以按需申请模型服务可下载的 HTTPS 地址；
- MiniMax H3、Seedance 2.5 等渠道可以读取参考素材；
- 同一内容重复上传时复用服务端文件；
- 不配置后端时现有视频生成流程保持不变。

### 4.2 第二阶段目标

- 配置弹窗增加独立的“服务器备份”入口；
- 支持将画布、素材、生成记录和本地媒体备份到服务器；
- 支持查看服务器快照并恢复到当前浏览器；
- 使用清单对比，只上传服务器缺少的媒体文件；
- 同步过程可取消、可显示进度，失败后不提交不完整快照；
- 主体功能落地后，将主体数据作为独立同步域接入。

### 4.3 后续可选目标

- 多用户账号和数据隔离；
- 自动双向同步；
- 多设备冲突解决；
- 团队空间和共享画布；
- 服务端渠道密钥托管；
- 对象存储；
- 管理后台、配额和计费。

### 4.4 非目标

第一版不做以下事项：

- 不把后端改成画布实时编辑的唯一数据源；
- 不让每次节点拖动、缩放或文本输入都请求服务器；
- 不移除 localforage 和 WebDAV；
- 不默认上传 AI API Key 或 WebDAV 凭据；
- 不在前端仓库中实现完整账号系统；
- 不直接公开整个同步媒体目录；
- 不在第一次接入时引入 PostgreSQL、Redis、消息队列和对象存储组合。

## 5. 仓库边界

### 5.1 前端仓库职责

当前 `infinite-canvas` fork 负责：

- 本地业务数据读写；
- 云服务配置界面；
- 生成同步清单；
- 按需读取 localforage 中的媒体 Blob；
- 调用上传、备份、恢复和临时地址接口；
- 将远程媒体恢复到 localforage；
- 将模型访问 URL 转换为渠道所需字段；
- 展示连接、上传、同步与恢复状态。

前端不关心后端使用 SQLite、PostgreSQL、磁盘还是对象存储。

### 5.2 独立后端仓库职责

建议创建独立仓库：

```text
infinite-canvas-cloud/
├── src/
│   ├── server.ts
│   ├── config.ts
│   ├── auth/
│   ├── media/
│   ├── sync/
│   ├── snapshots/
│   └── storage/
├── migrations/
├── package.json
├── README.md
├── Dockerfile
└── docker-compose.yml
```

后端负责鉴权、文件校验、内容哈希、媒体保存、同步快照、模型访问 URL、数据删除和版本化 API。服务端密钥只存在后端运行环境，不进入前端仓库。

### 5.3 独立仓库的收益

- 上游同步不会进入后端目录；
- 后端可以单独部署和回滚；
- 服务端依赖不会进入前端安装流程；
- 服务端配置与密钥不会混入静态前端；
- 更换数据库或存储实现时，前端协议可以保持不变；
- 开源用户仍可完全不部署后端。

## 6. 前端最小接入设计

### 6.1 建议新增文件

```text
web/src/services/cloud-client.ts
web/src/services/cloud-media.ts
web/src/services/cloud-sync.ts
web/src/services/sync-transport.ts
web/src/hooks/use-cloud-sync.ts
web/src/stores/use-cloud-config-store.ts
web/src/components/layout/cloud-sync-settings.tsx
web/src/types/cloud.ts
```

### 6.2 尽量少改的现有文件

```text
web/src/components/layout/app-config-modal.tsx
web/src/services/app-sync.ts
web/src/services/api/video.ts
web/src/i18n/locales/zh-CN.ts
web/src/i18n/locales/en-US.ts
```

接入规则：

- 配置弹窗只新增页签或面板入口；
- `app-sync.ts` 通过传输接口复用现有同步算法；
- `video.ts` 只在渠道要求远程 URL 时调用媒体解析函数；
- 页面和画布组件不得直接拼接云端请求；
- 云端状态不得散落到多个业务 store。

### 6.3 云服务配置

```ts
type CloudConfig = {
    enabled: boolean;
    baseUrl: string;
    accessToken: string;
};
```

配置保存在当前浏览器。服务器备份不得包含 `accessToken`。导出配置仍需明确提示文件可能包含敏感凭据。

### 6.4 同步传输接口

```ts
type RemoteFileMeta = {
    path: string;
    sha256: string;
    bytes: number;
    mimeType: string;
};

interface SyncTransport {
    getManifest(domain: string): Promise<unknown | null>;
    putManifest(domain: string, manifest: unknown): Promise<void>;
    findMissingFiles(files: RemoteFileMeta[]): Promise<string[]>;
    putFile(file: RemoteFileMeta, blob: Blob): Promise<void>;
    getFile(sha256: string): Promise<Blob>;
}
```

WebDAV 与 Cloud 各自实现该接口，同步算法不关心底层传输方式。

### 6.5 媒体远程引用

本地业务对象继续以 `storageKey` 为主要引用。需要长期复用的主体或素材可以增加：

```ts
type RemoteMediaReference = {
    provider: "cloud";
    mediaId: string;
    sha256: string;
};
```

模型请求前调用统一入口：

```ts
async function resolveModelMediaUrl(input: {
    storageKey?: string;
    remote?: RemoteMediaReference;
    purpose: "reference-image" | "reference-video" | "reference-audio";
}): Promise<string>;
```

解析过程：

1. 已有 `mediaId` 时，向后端申请模型访问 URL；
2. 没有远端引用时，从 localforage 读取 Blob；
3. 上传 Blob 并保存后端返回的 `mediaId` 与哈希；
4. 申请模型访问 URL；
5. 将 URL 交给具体模型适配器。

业务数据不保存带签名的临时 URL，避免过期地址进入画布和同步快照。

## 7. 后端 API 协议

接口统一使用 HTTPS 和版本前缀：

```text
/api/cloud/v1
```

错误响应使用稳定代码：

```json
{
  "error": {
    "code": "MEDIA_TYPE_NOT_ALLOWED",
    "message": "不支持该文件类型",
    "requestId": "req_xxx"
  }
}
```

前端根据 `code` 映射用户文案，不依赖自由文本判断业务状态。

### 7.1 服务状态

```http
GET /api/cloud/v1/status
Authorization: Bearer <token>
```

```json
{
  "service": "infinite-canvas-cloud",
  "apiVersion": 1,
  "storageVersion": 1,
  "capabilities": {
    "media": true,
    "snapshots": true,
    "bidirectionalSync": false
  }
}
```

前端先检查协议版本和能力列表。未知主版本应拒绝写入。

### 7.2 检查缺少的媒体

```http
POST /api/cloud/v1/media/missing
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "files": [
    {
      "sha256": "<sha256>",
      "bytes": 123456,
      "mimeType": "audio/mpeg"
    }
  ]
}
```

响应：

```json
{
  "missing": ["<sha256>"]
}
```

### 7.3 上传媒体

```http
POST /api/cloud/v1/media
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 原始媒体 Blob |
| `sha256` | 是 | 前端计算的哈希，服务端必须重新计算 |
| `purpose` | 是 | `sync`、`reference-image`、`reference-video` 或 `reference-audio` |
| `filename` | 否 | 只作下载名称，不作为存储路径 |

```json
{
  "media": {
    "id": "media_xxx",
    "sha256": "<sha256>",
    "bytes": 123456,
    "mimeType": "audio/mpeg"
  }
}
```

服务端不得信任扩展名、浏览器声明的 MIME 或前端哈希。哈希不一致时拒绝入库。

### 7.4 私有媒体读取

```http
GET /api/cloud/v1/media/:mediaId/content
Authorization: Bearer <token>
```

该接口供浏览器恢复数据，必须鉴权。

### 7.5 申请模型访问 URL

```http
POST /api/cloud/v1/media/:mediaId/access-url
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "purpose": "model-reference",
  "provider": "minimax"
}
```

```json
{
  "url": "https://infinite.zemra.cn/media-access/<signed-token>/voice.mp3",
  "expiresAt": "<ISO 8601>"
}
```

签名令牌只允许读取一个媒体文件，并包含用途和过期时间。有效期必须覆盖渠道排队和下载素材的时间，默认值实施前确认。

### 7.6 备份会话与快照

```http
POST /api/cloud/v1/backups
POST /api/cloud/v1/backups/:backupId/commit
GET  /api/cloud/v1/backups
GET  /api/cloud/v1/backups/:backupId
```

创建备份时，后端根据清单返回缺少的媒体。提交前服务端确认所有文件存在、哈希一致、业务域格式有效、数据版本受支持，并保证重复提交相同备份是幂等的。未提交备份不能进入可恢复快照列表。

## 8. 同步数据格式

### 8.1 独立版本

必须分别管理：

```text
apiVersion       云服务通信协议版本
storageVersion   云端持久化结构版本
domain.version   单个业务域的数据格式版本
```

API 升级不应强制迁移所有快照；某个业务域升级也不应隐式改变其他业务域。

### 8.2 备份清单

```ts
type BackupManifest = {
    app: "infinite-canvas";
    version: 1;
    backupId: string;
    createdAt: string;
    clientId: string;
    sourceCommit?: string;
    domains: Array<{
        name: string;
        version: number;
        data: unknown;
        files: Array<{
            storageKey: string;
            sha256: string;
            bytes: number;
            mimeType: string;
        }>;
    }>;
};
```

`sourceCommit` 只用于诊断，兼容性由显式格式版本决定。

### 8.3 业务域

| 域 | 内容 |
| --- | --- |
| `canvas` | 画布项目、节点、连线和删除标记 |
| `assets` | 我的素材和媒体引用 |
| `image-logs` | 图片生成记录 |
| `video-logs` | 视频生成记录 |
| `subjects` | 后续新增的主体、人物图、参考音频、默认提示词和渠道引用 |

偏好设置是否同步需单独确认。AI API Key、WebDAV 凭据和 Cloud Token 不进入任何业务域。

## 9. 备份、恢复与冲突策略

### 9.1 第一版语义

界面提供两个明确动作：

- `备份到服务器`：以当前浏览器数据创建新的不可变快照；
- `从服务器恢复`：选择快照，将其导入或恢复到当前浏览器。

第一版不使用含义模糊的“自动同步”，避免用户误认为两台设备会实时合并。

### 9.2 备份流程

```text
读取本地业务域
    ↓
收集 storageKey
    ↓
读取媒体 Blob 并计算哈希
    ↓
创建备份会话
    ↓
上传服务器缺少的媒体
    ↓
上传业务域清单
    ↓
服务端校验完整性
    ↓
原子提交快照
```

取消或失败时，未提交会话不能显示为完整备份。

### 9.3 恢复流程

```text
选择服务器快照
    ↓
检查格式版本
    ↓
下载并校验媒体
    ↓
准备浏览器恢复数据
    ↓
用户确认恢复方式
    ↓
写入各 localforage 实例
    ↓
重新加载应用状态
```

恢复至少区分“导入为新项目”和“恢复对应业务域”。覆盖范围必须明确，不能把恢复静默解释为清空全部本地数据。

### 9.4 后续双向同步

自动双向同步需要稳定 ID、逻辑版本、删除标记、客户端 ID 和冲突版本。画布冲突不得通过记录数量或文件大小自动决定胜负；无法安全合并时保留两个副本。

## 10. 媒体存储设计

### 10.1 文件与元数据分离

索引或数据库保存 `mediaId`、内容哈希、字节数、检测后的 MIME、所有者、创建时间、引用状态和物理存储键。文件系统或对象存储保存原始字节，普通业务记录不保存 Base64。

### 10.2 内容寻址

建议物理路径为：

```text
data/files/<sha256前两位>/<完整sha256>
```

用户文件名只用于展示。后端禁止将用户文件名直接拼入磁盘路径。

### 10.3 私有文件与模型访问

```text
/api/cloud/v1/media/:id/content       浏览器鉴权读取
/media-access/:signedToken/:filename  模型临时读取
```

模型地址不包含主访问令牌，返回文件字节而不是 HTML 预览页。

### 10.4 模型请求映射

MiniMax H3 和 Seedance 2.5 的原生兼容形式：

```json
{
  "type": "audio_url",
  "audio_url": {
    "url": "<cloud access url>"
  },
  "role": "reference_audio"
}
```

使用 `audio_urls` 数组的渠道适配器只改变请求结构，不改变云端媒体服务。

## 11. 鉴权与权限

### 11.1 个人部署第一版

- 使用单一访问令牌；
- 令牌只保存在浏览器本地和服务器环境变量；
- 不写入 Git、构建产物、URL 查询参数或部署文档；
- 所有写接口要求 `Authorization: Bearer`；
- Nginx 和应用日志不记录 Authorization；
- 支持轮换令牌；
- 模型媒体地址不暴露主令牌。

### 11.2 多用户扩展

多用户模式中，每个媒体、清单和快照绑定用户 ID。所有按 ID 访问的接口先检查所有权，不能只依赖 ID 难以猜测。

### 11.3 同域部署

```text
https://infinite.zemra.cn/             静态前端
https://infinite.zemra.cn/api/cloud/   反向代理到后端
https://infinite.zemra.cn/media-access/模型临时读取
```

同域部署可以减少 CORS 配置。若使用独立域名，只允许明确配置的前端来源。

## 12. 安全要求

- 所有公网请求使用 HTTPS；
- 上传内容按真实文件特征校验；
- 禁止将上传文件作为脚本或 HTML 执行；
- 媒体响应增加 `X-Content-Type-Options: nosniff`；
- 文件目录不能位于前端 release 内；
- 不允许目录列表；
- 路径参数必须防止路径穿越；
- 临时签名绑定单个媒体 ID、用途和过期时间；
- 删除操作必须验证所有权；
- 日志不记录访问令牌、签名 URL 全文或媒体内容；
- 恢复前校验清单版本、结构和文件哈希；
- 未知版本、损坏清单和哈希冲突时拒绝覆盖原数据；
- 持久化格式迁移前先创建可验证备份；
- 界面明确说明人物图和声音上传位置与用途。

## 13. 持久化选择

### 13.1 第一版

- SQLite 保存媒体索引、备份会话和快照元数据；
- 服务器独立数据目录保存媒体和快照清单；
- SQLite 不保存大媒体 Blob；
- Nginx 只转发经过应用鉴权或签名验证的路径。

### 13.2 后续扩展

多实例或较大规模时，可换成 PostgreSQL 保存元数据，S3、R2、OSS、COS 或 MinIO 保存媒体。前端 API 不因持久化实现变化而改变。

## 14. 部署设计

### 14.1 网络边界

```text
Internet
   ↓
Nginx :443
├── /                → 当前静态前端
├── /api/cloud/      → 127.0.0.1:<cloud-port>
└── /media-access/   → 127.0.0.1:<cloud-port>
```

后端只监听服务器本机。具体端口实施前确认。

### 14.2 服务器目录

```text
/srv/infinite-canvas-cloud/
├── releases/
├── current -> releases/<release-id>
├── data/
│   ├── database/
│   ├── files/
│   └── snapshots/
└── config/
```

应用 release 可以切换，`data/` 是共享持久化目录。部署和回滚不得覆盖用户数据。

### 14.3 进程与回滚

首次部署前检查服务器现有 systemd、PM2 或 Docker 使用情况，再选择匹配方式。发布前记录应用 release、数据库版本、数据目录备份和 Nginx 配置备份。代码回滚与数据迁移回滚分开管理。

## 15. Fork 持续同步策略

### 15.1 Git 远端

前端 fork 保留：

```text
origin    自己的 fork
upstream  原始开源仓库
```

后端仓库单独使用自己的 `origin`，不参与前端 upstream 合并。

### 15.2 提交组织

```text
feat(cloud): add optional cloud configuration
feat(cloud): add media upload client
feat(cloud): add backup transport
feat(video): resolve remote reference media urls
```

上游同步、云端接入、格式化和无关重构不放在同一个提交中。

### 15.3 冲突控制

优先新增 `cloud-*` 文件。对上游活跃文件只保留窄入口：配置弹窗引用一个组件、同步服务接收一个 transport、视频服务调用一个媒体 URL 解析函数。登录、上传和同步逻辑不得散落到画布页面与节点组件。

### 15.4 上游数据格式变化

1. 先合并上游；
2. 检查导入导出和 WebDAV 清单变化；
3. 只升级受影响业务域版本；
4. 保留旧快照只读能力或提供显式迁移；
5. 验证未配置后端时的原有行为；
6. 验证备份、恢复和媒体引用。

## 16. 分阶段实施计划

### 阶段一：协议与媒体托管

后端建立独立仓库，实现状态、媒体检查、上传、私有下载和模型访问 URL，配置持久化目录、HTTPS、Nginx 路由及回滚文档。

前端增加可选云配置、连接测试、媒体上传客户端，并为要求 URL 的视频模型提供统一解析入口。

验收重点：H3 和 Seedance 渠道能够在任务处理期间下载完整参考图片和音频。

### 阶段二：服务器备份与恢复

后端实现备份会话、缺失文件检查、原子提交、快照列表和快照详情。前端抽取同步传输接口，复用 WebDAV 的业务域整理与文件收集，增加备份、恢复、进度和取消。

### 阶段三：主体库

- 新增本地主体 store；
- 保存人物图、参考音频和默认提示词；
- 保存 Cloud `mediaId`，不保存临时签名 URL；
- 将主体作为 `subjects` 域纳入备份；
- 按渠道映射为 H3、Seedance 或其他模型请求。

### 阶段四：多用户与自动同步

只有明确需要公开多用户服务时进入该阶段，重新评估身份认证、数据库、对象存储、配额、冲突策略和隐私要求。

## 17. 验收标准

### 17.1 兼容性

- 未配置 Cloud 时，画布、素材、生成记录、WebDAV 和 AI 渠道行为不变；
- Cloud 离线时，本地编辑仍可继续；
- 不支持的 API 版本不会写入服务器；
- 不支持的快照版本不会覆盖浏览器数据。

### 17.2 媒体

- 同一内容重复上传后复用相同服务端文件；
- 服务端重新计算的哈希与客户端一致；
- 私有内容接口未鉴权时不可访问；
- 模型访问 URL 只能读取指定文件；
- H3/Seedance 能在任务处理期间下载完整媒体；
- 过期模型访问 URL 无法继续使用；
- 媒体响应类型与内容一致。

### 17.3 备份

- 首次备份包含所有选定业务域及媒体；
- 再次备份只上传服务端缺少的媒体；
- 上传中断不会生成可恢复的完整快照；
- 恢复后画布、素材、记录和媒体引用完整；
- API Key、WebDAV 密码和 Cloud Token 不在快照中；
- 文件损坏或哈希不一致时停止恢复并保留原本地数据。

### 17.4 Fork 维护

- 云端功能主要位于新增文件；
- 上游核心文件只包含必要接入口；
- 合并上游后可以禁用 Cloud 验证原始行为；
- 后端发布与前端发布可以独立回滚。

## 18. 实施前待确认事项

以下配置会改变实际行为，编码前需要确认：

1. 第一版是个人单令牌模式，还是一开始支持多用户登录；
2. 服务器备份创建快照，还是覆盖唯一远端副本；
3. 恢复默认导入副本，还是覆盖当前业务域；
4. 允许同步哪些业务域，偏好设置是否包含在内；
5. 单个图片、音频和视频文件允许的大小；
6. 单个用户或单令牌的总存储上限；
7. 同时上传文件的并发上限；
8. 上传和下载超时；
9. 失败后的重试次数与退避方式；
10. 模型访问 URL 的有效期；
11. 快照保留数量和清理方式；
12. 删除主体时立即删除媒体，还是等待引用回收；
13. 使用当前站点同域路径，还是独立 API 域名；
14. 第一版使用服务器磁盘还是对象存储；
15. H3 和 Seedance 实际渠道接受的 URL、格式、时长和可访问性要求。

## 19. 推荐的第一版范围

- 独立 `infinite-canvas-cloud` 仓库；
- 当前服务器部署一个只监听本机的后端服务；
- Nginx 同域转发 `/api/cloud/` 和 `/media-access/`；
- 单访问令牌鉴权；
- SQLite 只保存索引与快照元数据；
- 服务器独立数据目录保存媒体；
- 前端增加云服务配置与测试连接；
- 本地媒体按需上传；
- 为 H3/Seedance 生成受限媒体访问 URL；
- 增加手动“备份到服务器”和“从服务器恢复”；
- 不做自动双向同步、多人注册、团队空间和服务端 API Key 托管。

该范围能够解决参考音频 URL、服务器备份和后续主体库的基础需求，同时将当前 fork 对上游代码的长期差异控制在少量服务与配置接入文件中。
