# Infinite Canvas 自定义 UI 设计方案

## 1. 方案目的

本方案用于指导 Infinite Canvas 在保留现有功能、数据结构和生成能力的基础上，重新设计全部页面布局、导航体系、操作流程和视觉风格。

设计目标不是给现有页面换一套颜色，而是根据用户真实创作任务重新组织产品：让画布成为创作中心，让图片、视频、音频和主体成为可组合的资源，让模型渠道和同步配置退出日常操作路径，同时控制当前 fork 与上游仓库的长期冲突范围。

本文是临时设计方案，不代表相关界面已经实现。实施时应按阶段完成，每一阶段保持应用可运行，不一次性替换全部页面。

## 2. 核心结论

采用“同一套前端、重新设计 UI、复用业务能力”的方式：

```text
保留并复用
├── services/api          模型与外部服务请求
├── stores                全局业务状态
├── lib/canvas            画布计算与工具
├── image-storage         图片本地存储
├── file-storage          音视频本地存储
├── app-sync              WebDAV 数据同步
└── types                 业务数据类型

重新设计
├── router                产品信息架构
├── layouts               应用整体布局
├── pages                 页面任务流
├── components/layout     导航和全局面板
├── 页面私有 components   功能呈现
├── 画布外围 UI           工具栏、面板、状态区
└── app-theme             视觉语言和主题
```

不维护第二套完整前端，不复制模型请求、存储和画布业务代码。上游新增功能时，先同步业务能力，再按本方案的信息架构接入自定义 UI。

## 3. 产品定位

### 3.1 产品角色

Infinite Canvas 是一个面向 AI 内容创作的本地优先工作台。用户可以在独立工作台中快速生成单项内容，也可以在无限画布中组织图片、视频、音频、文本、模型配置和 Agent 流程。

### 3.2 主要用户

- 需要快速试验多个模型的个人创作者；
- 制作图片、短视频和配音的内容团队；
- 需要反复使用人物、产品和声音参考的创作者；
- 使用节点画布组织复杂生成流程的高级用户；
- 希望使用自己的渠道和 API Key 的自托管用户。

### 3.3 用户最常完成的任务

1. 输入提示词，快速生成图片；
2. 使用人物图、产品图、参考视频或音频生成视频；
3. 将素材拖入画布并组合成生成流程；
4. 查看、筛选和复用历史生成结果；
5. 保存常用主体及其人物图、参考音色和提示词；
6. 配置模型渠道、调用脚本和本地代理；
7. 备份、恢复或同步浏览器本地数据；
8. 让 Agent 读取和操作当前画布。

## 4. 设计方向

### 4.1 视觉概念：安静的数字创作室

整体采用克制、精确、低视觉重量的创作工具风格。界面不使用大面积营销渐变、玻璃拟态卡片墙或夸张发光效果。内容是视觉中心，控件在需要时出现，空白区域帮助用户理解层级。

主要特征：

- 大面积平静背景承载作品；
- 清晰的内容层级和紧凑的工具密度；
- 顶部工具栏融入页面，无边框、无阴影、无胶囊容器；
- 普通操作使用透明背景和轻微 hover；
- 选中状态使用明确但克制的强调色；
- 图片和视频直接成为界面视觉主体；
- 文本、音频和配置节点使用图标、排版与细线区分，不堆叠灰色块；
- 动效用于解释状态变化，不用于装饰。

### 4.2 记忆点

产品的核心记忆点是“作品围绕当前任务自然展开”：

- 在普通工作台中，参数围绕生成结果排列；
- 在画布中，工具围绕选中内容出现；
- 在主体库中，人物图、声音和默认提示词构成一张可直接调用的创作身份卡；
- 在 Agent 中，对话与画布引用保持同一上下文。

### 4.3 设计原则

1. 内容优先：减少永久占据空间的面板。
2. 渐进展开：先显示常用设置，高级参数按需展开。
3. 就近操作：对象操作靠近选中对象，系统操作集中到全局区域。
4. 状态明确：选中、运行、等待、失败和完成具有稳定表达。
5. 一致模型：图片、视频、音频和主体使用相同的选择、预览和引用方式。
6. 本地优先：同步和云端不可用不阻塞本地创作。
7. 主题统一：颜色来自 `canvasThemes`、`useThemeStore` 和 Ant Design token。
8. 低冲突：UI 逻辑尽量位于新增布局、页面私有组件和 hook 中。

## 5. 信息架构

### 5.1 一级导航

```text
创作
├── 无限画布
├── 图片创作
├── 视频创作
└── 音频创作

资源
├── 我的素材
├── 主体库
└── 生成记录

系统
├── Agent
└── 设置
```

主导航只展示高频入口。渠道、WebDAV、本地代理和导入导出集中到设置，不与创作入口并列。

### 5.2 路由建议

```text
/                         最近项目或默认画布
/canvas                   画布项目列表
/canvas/:projectId        画布编辑器
/image                    图片创作
/video                    视频创作
/audio                    音频创作
/assets                   我的素材
/subjects                 主体库
/history                  生成记录
/agent                    独立 Agent 工作区（可选）
/settings/providers       模型与渠道
/settings/network         本地代理
/settings/data            本地存储与同步
/settings/appearance      外观
```

设置可以保持 Modal，也可以升级为路由页面。第一阶段优先保留现有 Modal，等其他页面稳定后再决定是否改成独立设置中心。

### 5.3 全局导航层级

桌面端采用窄侧栏：

```text
┌──────┬────────────────────────────────────────────┐
│ Logo │ 当前页面标题 / 项目名称          全局操作 │
│      ├────────────────────────────────────────────┤
│ 画布 │                                            │
│ 图片 │                 页面内容                   │
│ 视频 │                                            │
│ 音频 │                                            │
│ 素材 │                                            │
│ 主体 │                                            │
│      │                                            │
│Agent │                                            │
│ 设置 │                                            │
└──────┴────────────────────────────────────────────┘
```

侧栏默认只显示图标和必要状态，宽度允许时显示文字。项目内部工具不放进全局侧栏。

移动端使用底部主导航和全屏二级页面，不把桌面侧栏压缩成横向滚动区域。

## 6. 全局布局

### 6.1 应用外壳

应用外壳负责：

- 全局导航；
- 当前页面标题或画布项目名称；
- 主题切换；
- 连接和同步状态；
- 设置入口；
- 全局消息和确认弹窗容器。

应用外壳不接收大量业务 props。需要渠道、主题或同步状态时，直接读取对应全局 store 或 hook。

### 6.2 顶部区域

普通页面顶部包含：

```text
页面名称    简短状态/数量                         主操作
```

例如素材页：

```text
我的素材    128 项                    搜索  筛选  上传
```

避免每个页面使用大标题卡片、说明卡片和重复面包屑。

### 6.3 内容宽度

- 画布占满剩余视口；
- 图片、视频、音频工作台使用左右分区或上下结果区；
- 素材和主体库使用自适应网格；
- 设置内容保持可阅读宽度，不铺满超宽屏；
- Modal 只用于短任务，复杂配置进入抽屉或独立页面。

## 7. 无限画布页面

### 7.1 页面目标

让用户在最大可用空间中组织创作流程。永久可见的 UI 只保留项目入口、核心工具、视图控制和运行状态。

### 7.2 桌面布局

```text
┌────────────────────────────────────────────────────────────┐
│ 返回  项目名称                         撤销 重做 Agent 导出 │
├────────┬───────────────────────────────────────┬───────────┤
│ 项目   │                                       │ 当前对象  │
│ 素材   │              无限画布                 │ 参数/生成 │
│ 节点   │                                       │           │
│ 主体   │                                       │           │
│        │                                       │           │
├────────┴───────────────────────────────────────┴───────────┤
│ 选择/移动                         运行状态        缩放/适配 │
└────────────────────────────────────────────────────────────┘
```

左右面板均可折叠。没有选中对象时，右侧面板关闭或显示轻量提示，不长期占据画布。

### 7.3 顶部栏

遵循当前画布规范：

- 无外框、无阴影、无胶囊背景；
- 项目名可以原地编辑；
- 撤销、重做和导出使用图标加 Tooltip；
- Agent 作为文字按钮或状态入口；
- 保存状态采用轻量文本，例如“已保存”“正在保存”；
- 不显示重复的页面标题和项目标题。

### 7.4 左侧资源面板

采用单列功能切换：

```text
项目｜素材｜节点｜主体
```

每次只展示一个面板内容。列表里的非图片缩略图不使用 `theme.node.fill` 作为装饰背景，图标直接显示。普通“添加”操作采用透明按钮和轻微 hover。

### 7.5 右侧属性面板

根据选中对象变化：

| 选中对象 | 面板内容 |
| --- | --- |
| 图片节点 | 图片信息、提示词、参考输入、编辑与生图 |
| 视频节点 | 视频信息、截帧、参考输入和视频生成 |
| 音频节点 | 音频信息、试听、参考输入和相关生成 |
| 文本节点 | 内容编辑、提示词用途和生成动作 |
| 配置节点 | 模型、尺寸、时长、数量和高级参数 |
| 组节点 | 组名、组内资源和解散操作 |
| 多选 | 对齐、分布、打组、删除和批量操作 |

节点主要操作保持在就近工具条中，右侧面板负责需要持续阅读或填写的属性。

### 7.6 节点视觉

- 图片和视频尽量直接展示内容；
- 节点标题与状态覆盖层保持轻量；
- 文本节点以排版为核心；
- 音频节点以波形、时长和播放为核心；
- 配置节点以模型和关键参数摘要为核心；
- 选中状态通过边线、连接点和工具条表达；
- 错误状态显示简短原因，并允许查看详情；
- 生成中状态使用稳定进度，不持续闪烁整张节点。

### 7.7 画布上下文操作

右键菜单只包含与点击位置相关的操作。新增节点使用可搜索的命令面板，支持键盘快速创建。多选操作集中在选择框上方，不重复出现在多个固定面板。

## 8. 图片创作页面

### 8.1 页面结构

```text
┌───────────────────────────────────────────────────────────┐
│ 图片创作                                  历史  保存到画布 │
├───────────────────┬───────────────────────────────────────┤
│ 提示词            │                                       │
│ 参考图片          │               生成结果                │
│ 模型              │                                       │
│ 比例 / 分辨率     │                                       │
│ 数量 / 高级设置   │                                       │
│                   │                                       │
│       生成        │                                       │
└───────────────────┴───────────────────────────────────────┘
```

左侧是紧凑创作参数，右侧是结果。参考图片以可排序缩略图展示。生成结果优先显示作品，不使用厚重卡片框。

### 8.2 参数层级

始终显示：

- 提示词；
- 模型；
- 参考图片；
- 比例；
- 分辨率；
- 生成数量；
- 生成按钮。

按需展开：

- 负面提示；
- 种子；
- 输出格式；
- 背景；
- 模型专属参数；
- 调用脚本诊断。

### 8.3 结果操作

结果悬停或选中后显示：

- 下载；
- 保存到素材；
- 发送到画布；
- 设为参考图；
- 再次生成；
- 查看生成参数。

## 9. 视频创作页面

### 9.1 页面结构

视频页沿用“参数＋结果”的基本骨架，但参考输入是核心区域：

```text
提示词
主体（可选）
参考图片
参考视频
参考音频
生成模式
模型 / 比例 / 清晰度 / 时长
配音 / 水印
生成
```

### 9.2 生成模式

用清晰的模式切换表达：

- 首尾帧；
- 全能参考。

模式切换后，只显示当前模式有效的输入位置。避免用户连接多个参考后才收到字段不兼容错误。

### 9.3 主体入口

主体不是普通下拉选项。选择主体后展示紧凑引用卡：

```text
[人物缩略图] 主体名称
人物图已设置 · 参考音色已设置 · 默认提示词已应用
```

用户可以单独取消人物图、音色或默认提示词，不需要删除整个主体。

### 9.4 参考音频

音频引用显示：

- 文件名或主体音色名；
- 时长；
- 播放/暂停；
- 是否已经上传云端；
- 渠道无法读取时的明确处理入口。

如果渠道只接受 URL，生成前由统一媒体服务自动解析，不让用户手工填写 `audio_url`。

## 10. 音频创作页面

页面围绕文本、音色、表达方式和结果波形组织：

```text
┌───────────────────┬───────────────────────────────────────┐
│ 台词              │ 波形 / 播放器                         │
│ 音色              │                                       │
│ 语速              │ 生成结果列表                          │
│ 指令              │                                       │
│ 格式              │ 保存到主体 / 素材 / 画布              │
│ 生成              │                                       │
└───────────────────┴───────────────────────────────────────┘
```

公共音色、复刻音色和主体音色在选择器中分组，不混成一条无法理解的模型值列表。

## 11. 我的素材

### 11.1 页面结构

```text
我的素材    搜索    类型筛选    来源筛选    排序    上传

[全部] [图片] [视频] [音频]

自适应内容网格
```

### 11.2 素材卡片

- 图片按原比例裁切预览；
- 视频显示封面和时长；
- 音频使用波形或简洁音频图标；
- 选中后在统一操作条显示批量操作；
- 元数据在详情抽屉展示，不挤占卡片；
- 卡片操作位置一致，避免每种媒体一套交互。

### 11.3 素材操作

- 添加到画布；
- 设为生成参考；
- 加入主体；
- 下载；
- 重命名；
- 查看来源；
- 删除。

## 12. 主体库

### 12.1 主体定义

主体由以下内容组成：

```text
主体
├── 名称
├── 人物或产品参考图
├── 参考音色
├── 默认提示词
├── 标签
└── 模型渠道远端引用
```

### 12.2 主体列表

主体卡以人物或产品图为核心，展示：

- 主体名称；
- 参考图数量；
- 是否包含音色；
- 最近使用时间；
- 云端媒体状态。

普通卡片不显示完整提示词和技术 ID。

### 12.3 主体详情

```text
┌────────────────────┬─────────────────────────────────────┐
│ 主视觉与参考图     │ 名称                                │
│                    │ 标签                                │
│                    │ 默认提示词                          │
│                    │ 参考音色播放器                      │
│                    │ 渠道媒体状态                        │
│                    │ 在图片/视频/画布中使用              │
└────────────────────┴─────────────────────────────────────┘
```

主体保存本地文件引用和稳定远端媒体 ID，不保存容易过期的临时模型访问 URL。

## 13. 生成记录

将图片、视频和音频记录统一到一个页面，通过类型筛选。每条记录展示输入摘要、模型、时间、状态和结果。

详情面板展示：

- 完整提示词；
- 参考素材；
- 模型与渠道；
- 关键参数；
- 错误详情；
- 再次生成；
- 添加到素材或画布。

记录页面不显示 API Key、签名媒体 URL 或内部请求头。

## 14. Agent 工作区

### 14.1 画布内 Agent

画布右侧 Agent 作为可展开面板存在，支持：

- 对话；
- 历史；
- 技能；
- 日志；
- 引用当前画布素材；
- 查看工具调用状态。

展开时压缩或覆盖画布的具体方式应保持稳定，不因消息长度反复改变画布尺寸。

### 14.2 独立 Agent 页面

如果保留独立 Agent 路由，适合查看长对话、技能管理和诊断日志。画布操作仍绑定明确项目，不默认操作最近打开但不可见的画布。

## 15. 设置中心

### 15.1 分类

```text
模型与渠道
├── 渠道
├── 默认模型
└── 模型调用脚本

网络
├── 本地代理
└── 连接诊断

数据
├── 本地存储
├── WebDAV
├── 服务器备份（后续）
└── 导入导出

外观
├── 主题
└── 画布偏好
```

### 15.2 设置交互

- 需要即时反馈的设置自动保存；
- 涉及凭据和较大影响的配置使用明确保存动作；
- 测试连接与保存配置分开；
- 错误显示在对应配置区域；
- 高级技术参数不默认展开；
- API Key、WebDAV 密码和同步令牌始终明确标识为敏感信息。

## 16. 视觉系统

### 16.1 颜色

颜色全部通过现有主题入口统一管理：

- 页面背景；
- 面板背景；
- 主文字；
- 次文字；
- 分隔线；
- 强调色；
- 成功、警告和错误状态；
- 画布节点和连线状态。

业务组件不硬编码黑、白、stone 或 slate 色值。Ant Design 弹层背景、hover 和选中态通过 `web/src/lib/app-theme.ts` 的 Alias Token 与组件 Token 配置。

### 16.2 排版

- 中文正文优先选择清晰、紧凑且适合工具界面的字体栈；
- 数字、尺寸、时间和模型参数使用等宽数字特征；
- 页面标题克制，不使用营销型超大字号；
- 提示词和长文本保证舒适行高；
- 工具栏文字比正文更紧凑；
- 重要状态通过层级和位置表达，不依赖全部加粗。

### 16.3 间距

建立统一间距层级：

```text
4    图标与文字的紧密关系
8    小控件内部间距
12   紧凑组件间距
16   标准内容间距
24   分组间距
32   页面区块间距
```

具体 token 可以沿用 Tailwind spacing，不在组件中随意出现大量不相关数值。

### 16.4 圆角与边框

- 输入框、菜单和普通面板使用统一中等圆角；
- 媒体缩略图根据内容比例使用轻量圆角；
- 画布顶部栏和状态信息不使用胶囊容器；
- 普通卡片使用细边线或背景层级，不同时堆叠边线与重阴影；
- 选中态优先使用边线和强调色。

### 16.5 阴影

阴影只用于真实悬浮层：

- Dropdown；
- Popover；
- Modal；
- 拖拽中的对象；
- 覆盖画布的临时面板。

页面卡片和固定侧栏不使用明显阴影。

### 16.6 图标

优先使用 `lucide-react` 或项目现有 Ant Design 图标。相同动作始终使用相同图标。纯图标按钮必须有 Tooltip 和可访问名称。

## 17. 动效

动效用于表达：

- 面板展开与折叠；
- 生成结果出现；
- 素材拖入画布；
- 节点选中和工具条出现；
- 同步进度；
- 成功与失败状态变化。

避免：

- 所有按钮持续缩放；
- 大面积发光；
- 无限循环背景动画；
- 生成中整页闪烁；
- 多个面板同时从不同方向进入。

React 复杂动效优先使用项目已有 Motion，简单 hover 和展开使用 CSS。

## 18. 响应式设计

### 18.1 桌面端

- 完整侧栏；
- 创作页左右分区；
- 画布左右面板可同时打开；
- Agent 可作为右侧面板；
- 快捷键和悬停操作完整可用。

### 18.2 平板

- 全局侧栏收窄；
- 创作参数成为可收起面板；
- 画布一次只打开一个侧面板；
- Agent 使用覆盖式抽屉；
- 保留触控友好的操作尺寸。

### 18.3 手机

- 主导航位于底部或全屏菜单；
- 图片、视频和音频页改为“参数 → 结果”的分步结构；
- 素材使用双列或单列网格；
- 设置进入独立页面；
- 画布提供基础查看和有限编辑，不照搬桌面三栏布局；
- 不产生横向页面滚动。

## 19. 空状态、加载与错误

### 19.1 空状态

空状态直接引导第一个有效动作：

- 空画布：添加素材、创建生成节点或让 Agent 开始；
- 空素材库：上传或保存一次生成结果；
- 空主体库：创建主体并添加参考图或音色；
- 空生成记录：进入对应工作台生成内容。

避免使用与功能无关的大插画占据页面。

### 19.2 加载状态

- 页面首次加载使用骨架或局部占位；
- 生成任务保留已有内容，只更新任务区域；
- 同步显示阶段、文件数量和已处理体积；
- 长操作提供取消入口；
- 不因局部请求清空整个页面。

### 19.3 错误状态

错误文案说明：

1. 哪一步失败；
2. 用户当前数据是否安全；
3. 可以采取什么操作；
4. 是否可以重试。

技术详情放在展开区域，普通用户先看到可执行信息。

## 20. 无障碍与键盘操作

- 所有图标操作提供可访问名称；
- 焦点样式在浅色和深色主题下清晰；
- Modal 和抽屉正确管理焦点；
- 颜色不作为唯一状态表达；
- 画布快捷键不劫持输入框和可编辑文本；
- 菜单支持方向键、Enter 和 Esc；
- 生成结果和素材可通过键盘选择；
- 支持系统减少动态效果设置；
- 文字与背景满足合理对比度。

## 21. 与现有代码的边界

### 21.1 尽量保留

```text
web/src/services/api/
web/src/services/image-storage.ts
web/src/services/file-storage.ts
web/src/services/app-sync.ts
web/src/lib/canvas/
web/src/stores/
web/src/types/
canvas-agent/
canvas-proxy/
```

UI 重设计不得为了方便展示而随意改变本地存储结构和模型协议。

### 21.2 主要重做

```text
web/src/layouts/
web/src/pages/
web/src/components/layout/
页面目录下的 components/
画布工具栏和外围面板
web/src/lib/app-theme.ts
web/src/router.tsx
```

### 21.3 混合文件

以下区域往往同时包含 UI 和复杂业务：

```text
web/src/pages/canvas/project.tsx
web/src/components/canvas/
```

改造时只将确实复杂、能够独立验证的逻辑提取到页面私有 hook 或同目录工具。不要为了形式创建只转发 props 的组件。

## 22. 降低 fork 冲突的实现策略

### 22.1 将自定义 UI 放在明确边界内

新增页面私有组件时使用：

```text
web/src/pages/<page>/components/
```

页面私有 hook 使用：

```text
web/src/pages/<page>/use-*.ts
web/src/pages/<page>/hooks/
```

多个页面真正复用后再移到全局目录。

### 22.2 保持业务入口稳定

UI 通过少量 hook 读取 store 和服务：

```text
自定义 UI
    ↓
页面 hook / 全局 hook
    ↓
store / service / canvas lib
```

避免几十个组件直接理解模型协议、localforage 表名或 WebDAV 清单。

### 22.3 上游同步分类

| 上游变更 | 处理方式 |
| --- | --- |
| 模型请求修复 | 优先合并业务实现 |
| 数据结构升级 | 合并类型、存储和转换逻辑 |
| 新画布操作 | 合并核心动作，再设计自定义入口 |
| 上游布局调整 | 不自动覆盖自定义布局 |
| 上游颜色和样式 | 仅评估功能影响 |
| 新页面功能 | 提取用户能力，按自定义信息架构接入 |

### 22.4 提交组织

```text
refactor(ui): isolate page behavior needed by custom layout
feat(ui): add redesigned application shell
feat(ui): redesign image workspace
feat(ui): redesign video workspace
feat(ui): redesign canvas workspace
style(theme): establish custom visual tokens
```

上游同步提交与 UI 设计提交分开。一次提交只处理一个页面或一类视觉系统，方便未来重放、比较和回退。

## 24. 页面验收清单

### 全局

- 主导航能在所有页面保持一致；
- 当前页面和选中状态清晰；
- 浅色、深色主题没有硬编码冲突；
- Dropdown、Menu、Select 等弹层颜色统一；
- 不出现不必要的重阴影和灰色按钮填充；
- 中文文案完整，英文模式不混入中文；
- 窄屏不出现横向滚动。

### 创作工作台

- 高频参数无需进入高级设置；
- 参考媒体可预览、排序和移除；
- 生成过程中仍可查看输入；
- 结果可以保存、下载、复用和发送到画布；
- 错误信息明确指出渠道、模型或素材问题。

### 画布

- 最大化可用画布空间；
- 左右面板可以独立折叠；
- 顶部栏与状态信息保持极简扁平；
- 选中对象后操作位置稳定；
- 图片节点保持原始比例；
- 非图片缩略图没有多余灰色底；
- 普通操作按钮透明，仅保留轻微 hover；
- 选择、移动、缩放、多选、连线和分组行为完整。

### 资源与主体

- 图片、视频和音频共享一致选择模型；
- 主体能够表达人物图、音色和默认提示词状态；
- 本地媒体和远端媒体状态不会混淆；
- 删除操作说明影响范围；
- 生成记录可以回溯输入与结果。

## 25. 风险与处理

### 25.1 UI 与业务逻辑耦合

风险：重做页面时复制复杂生成逻辑，导致以后上游修复无法同步。

处理：优先复用现有 service、store 和 lib；复杂页面逻辑提取到页面私有 hook，新 UI 只负责组织和呈现。

### 25.2 画布重构范围失控

风险：同时改布局、节点系统、事件系统和数据结构，难以定位问题。

处理：先改画布外围布局，再改面板和工具栏，最后调整节点视觉；每阶段保持交互逻辑稳定。

### 25.3 上游新增功能遗漏

风险：上游 UI 出现新入口，自定义 UI 没有对应功能。

处理：每次同步上游按类型、服务、store、页面四层检查，记录新增用户能力，再决定自定义入口。

### 25.4 两套视觉长期并存

风险：渐进改造期间新旧页面风格混杂。

处理：先完成全局主题和应用外壳，再逐页迁移；迁移完成的页面不再引用旧页面私有样式。

## 26. 最终建议

使用当前 `web/` 完成自定义 UI，不额外复制一套完整前端。布局、页面和视觉由当前 fork 控制，模型请求、本地存储、画布核心逻辑和数据类型尽量跟随上游。

实施顺序为：

```text
功能地图
    ↓
信息架构
    ↓
主题与应用外壳
    ↓
图片/视频/音频工作台
    ↓
素材与主体库
    ↓
画布外围布局
    ↓
节点视觉
    ↓
设置与 Agent
    ↓
响应式和完整验收
```

这种方式允许根据功能完全重新设计 UI，同时把后续 fork 同步工作集中在业务能力接入和少量混合文件中，而不是继续合并上游的旧布局和样式。
